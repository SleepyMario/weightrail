# Arch Linux / AUR packaging

This directory contains the local AUR candidate for stable package
`weightrail` version 0.2.0-1. It has not been published to the AUR.

## Package design

The package builds the tagged GitHub source archive with the standard PEP 517
setuptools workflow. The installed base command needs Python, NumPy, and
SQLite. Terminal graphs remain optional because `python-plotext` is currently
an AUR rather than an official-repository package. The GTK launcher is
installed and needs `python-gobject`, `gtk3`, and `python-matplotlib` at
runtime.

Both `weightrail` and `weightrail-gui` are installed below `/usr/bin`; the
Python package is installed in the system site-packages directory. The package
does not create a database or user state during build or installation.

## Clean container build

Validation uses the official Arch Linux base-devel image pinned by digest:

```text
docker.io/archlinux:base-devel@sha256:212b1e518e94ee9c52be55e8a32da75fcf11e7b5610b80b49479e67880102406
```

Inside a disposable container, update Pacman and install the official build,
check, and analysis tools:

```bash
pacman -Syu --noconfirm
pacman -S --noconfirm --needed python python-numpy sqlite python-build \
  python-installer python-setuptools python-wheel python-pytest namcap
```

Run `makepkg` as a non-root build user after copying this directory into that
user's writable build directory:

```bash
makepkg --verifysource
makepkg --cleanbuild --check --noconfirm
makepkg --printsrcinfo > .SRCINFO
namcap PKGBUILD
namcap weightrail-0.2.0-1-any.pkg.tar.zst
```

The source is downloaded before the build/check/package phases; those phases
need no network access. Local artifacts and logs belong under ignored `out/`.

## Installation validation

Use a second clean Arch container, mount only the built package, then let
Pacman resolve official runtime dependencies:

```bash
pacman -Syu --noconfirm
pacman -U --noconfirm /package/weightrail-0.2.0-1-any.pkg.tar.zst
tmpdir="$(mktemp -d)"
HOME="$tmpdir/home" XDG_DATA_HOME="$tmpdir/data" weightrail --help
HOME="$tmpdir/home" XDG_DATA_HOME="$tmpdir/data" weightrail --version
HOME="$tmpdir/home" XDG_DATA_HOME="$tmpdir/data" \
  weightrail --db-path "$tmpdir/weights.sqlite" 72.5
HOME="$tmpdir/home" XDG_DATA_HOME="$tmpdir/data" \
  weightrail --db-path "$tmpdir/weights.sqlite" stats
HOME="$tmpdir/home" XDG_DATA_HOME="$tmpdir/data" weightrail-gui --help
pacman -Ql weightrail
pacman -Rns --noconfirm weightrail
```

No display server is required for package validation. `weightrail-gui --help`
validates the launcher without importing GTK; normal GUI use requires the
three GUI optional dependencies listed above.

## Validation status

`makepkg --verifysource` passed, and the final offline
`makepkg --cleanbuild --check` ran all 44 upstream tests successfully. The
generated package is:

```text
weightrail-0.2.0-1-any.pkg.tar.zst
SHA-256: 09674ca74095d03e61847a085e33bd99eaf9e70e756f0370b42bb40856c6c713
```

`.SRCINFO` was generated from `PKGBUILD` with `makepkg --printsrcinfo` and
compared byte-for-byte with the checked-in candidate file.

Namcap produced no PKGBUILD warnings. Its package warnings were reviewed as
follows:

- The two `weightrail.*.main` module warnings are false positives for entry
  points whose target modules are present in the same package.
- The `gi`, `gi.repository.Gtk`, `matplotlib`, and `plotext` warnings describe
  imports that are deliberately covered by optional dependencies; the base
  CLI works without them.
- The `python` library warning is a false positive because `python` is an
  explicit runtime dependency.
- The apparently unneeded `sqlite` dependency is retained because Arch lists
  SQLite support as an optional integration of its Python package and this
  application requires `sqlite3` at runtime.

Direct archive inspection confirmed the package metadata, both launchers,
Python 3.14 system site-packages files, MIT license, and upstream README and
changelog. It found no `/usr/local`, source/build/test directory, source
archive, test cache, database, home directory, or temporary file. Python byte
code caches generated by makepkg are expected installed runtime files.

A second clean build also passed all 44 tests. Its payload file hashes and
metadata other than build time matched the first build, but its compressed
archive SHA-256 differed because makepkg recorded the later build timestamp in
`.PKGINFO`, `.BUILDINFO`, `.MTREE`, and archive entry times. Reproducibility is
therefore not claimed for builds made at different times without a shared
`SOURCE_DATE_EPOCH`.

The fresh-container test installed the first artifact with `pacman -U`, which
resolved NumPy and its official dependencies. `pacman -Qk` reported 46 entries
with none missing. CLI help/version, module imports, headless GUI help, and a
temporary 72.5 kg add/show/stats/summary workflow all passed. `pacman -Rns`
then removed the package and its newly installed dependencies; both commands
and every package-owned file were absent afterward.

## Later AUR publication

The public `v0.2.0` tag and GitHub release exist, and the package uses the tag
archive with a real SHA-256 checksum, so no replacement release tag is needed.
GitHub currently reports the release itself as not locked immutable; the fixed
PKGBUILD checksum nevertheless pins the approved archive bytes and makes a
changed archive fail source verification.
Before a later submission, review the final diff and validation results,
confirm the source checksum is still the expected immutable archive, import
`PKGBUILD` and `.SRCINFO` into an AUR package repository, commit there, and
push that repository. None of those AUR publication steps are performed here.
